# IRR计算N/A问题分析报告

## 问题概述

在批量IRR计算中，发现 **1,281条记录（占27%）** 的回本周期和IRR显示为N/A。本文档详细分析了问题的根本原因。

- **总记录数**: 4,752条
- **N/A记录数**: 1,281条
- **N/A占比**: 27%
- **主要分布**: 小系统（2-10块面板）的方案A和方案B

## 根本原因分析

### 1. 核心问题：投资成本远超系统收益能力

#### 成本结构失衡

以2块面板方案A为例：
```
面板成本: 0.44kW × 540 AUD/kW = 237.6 AUD
逆变器成本: 8kW × 280 AUD/kW = 2,240 AUD
电池成本: 22.44kWh × 865 AUD/kWh = 19,410.6 AUD
────────────────────────────────────────────
税前总成本: 21,888.2 AUD
GST(10%): 2,188.82 AUD
含税总成本: 24,077.02 AUD
减去补贴: 7,435.29 AUD
────────────────────────────────────────────
最终投资: 16,641.73 AUD
```

**问题**：
- 电池成本占税前总成本的 **88.7%**
- 电池成本甚至超过最终投资成本（因为有补贴）
- 配置极不合理：0.44kW的微型系统配22.44kWh的大电池

#### 收益能力不足

**年度发电量**：
```
0.44kW × 1526 kWh/kW/year = 671 kWh/year
```

**年度节省（理想情况，100%自用）**：
```
671 kWh × 0.30 AUD/kWh = 201.3 AUD/year
```

**月度电池计提**：
```
19,410.6 AUD ÷ 120个月 = 161.76 AUD/month
```

**月度净节省（前10年）**：
```
201.3 AUD/year ÷ 12 = 16.78 AUD/month（发电节省）
16.78 - 161.76 = -144.98 AUD/month（扣除电池计提后）
```

**结论**：前10年每月净节省为负数！

### 2. 为什么无法在20年内回本

#### 累计节省计算

**前10年（120个月）**：
- 月均节省约 -145 AUD
- 累计节省: -145 × 120 = -17,400 AUD（负数！）

**后10年（121-240个月）**：
- 月均节省约 +17 AUD（不再计提电池）
- 累计节省: +17 × 120 = +2,040 AUD

**20年总累计**：
```
-17,400 + 2,040 = -15,360 AUD
```

**对比初始投资**：
```
累计节省: -15,360 AUD
初始投资: 16,641.73 AUD
差距: 32,001.73 AUD
```

**结论**：不仅无法回本，反而累计亏损！

### 3. IRR计算为何返回null

#### IRR计算逻辑
```javascript
function calculateIRR(cashFlows, maxIterations = 100, tolerance = 1e-6) {
    if (cashFlows.length === 0 || cashFlows[0] >= 0) {
        return null;  // 条件1：第一项非负
    }
    
    // 二分法迭代
    for (let i = 0; i < maxIterations; i++) {
        // 寻找使NPV=0的贴现率
    }
    
    return null;  // 条件2：100次迭代未收敛
}
```

#### 现金流特征
```
Year 0: -16,641.73 AUD（初始投资）
Year 1: -1,740 AUD（前10年年均）
Year 2: -1,740 AUD
...
Year 10: -1,740 AUD
Year 11: +204 AUD（后10年年均）
Year 12: +204 AUD
...
Year 20: +204 AUD
```

#### NPV计算
```
NPV = -16,641.73 + Σ(现金流 / (1+r)^t)

当r=0%时: NPV = -16,641.73 + (-1,740×10) + (204×10) = -32,001.73
当r=50%时: NPV ≈ -16,641.73 + (负数) = 更大的负数
当r=100%时: NPV ≈ -16,641.73 + (接近0) = 接近-16,641.73
```

**结论**：在任何贴现率下，NPV都是负数，无法找到使NPV=0的解。

### 4. 回本周期为何为null

#### 回本逻辑
```javascript
if (paybackPeriodMonthly === null && 
    cumulativeSavingsMonthly >= config.investmentCost) {
    // 计算回本月数
}
```

#### 累计节省曲线
```
Month 1-120: 持续下降（负节省）
Month 121-240: 缓慢上升（正节省但幅度小）
Month 240: 累计节省仍为负数
```

**结论**：累计节省在240个月内始终 < 投资成本，变量保持为null。

## 问题性质判断

### 这是计算错误吗？

**❌ 不是计算错误**

计算逻辑完全正确，N/A是对不经济配置的真实反映：
- IRR无解 = 投资永远无法盈利
- 回本周期无解 = 20年内无法回本
- 这些配置在现实中确实不应该被推荐

### 这是设计问题吗？

**✅ 是Quote v1.1的设计问题**

#### 问题根源
1. **功率映射表设计不合理**
   - 方案A/B使用固定的GS/GD功率映射表
   - 小系统被分配了不经济的大电池
   - 没有考虑系统规模与电池容量的经济性匹配

2. **缺少经济性筛选**
   - Quote计算时未标记不经济配置
   - 所有配置都被输出，包括明显不合理的

3. **电池容量下限缺失**
   - 功率映射表中最小电池容量仍然过大
   - 对于微型系统（<2kW），应该有更小的电池选项

## 功率映射表分析

### GS功率映射表（方案A）
```javascript
{ min: 0, max: 5, nominal_battery_capacity_kwh: 22.44, inverter_kw: 8 }
```

**问题**：
- 0-5kW的系统统一配22.44kWh电池
- 对于0.44kW的系统，电池容量是光伏容量的 **51倍**
- 完全不符合经济性原则

### GD功率映射表（方案B）
```javascript
{ min: 0, max: 5, nominal_battery_capacity_kwh: 15.00, inverter_kw: 5 }
```

**问题**：
- 虽然比GS小，但15kWh对于0.44kW系统仍然过大
- 电池容量是光伏容量的 **34倍**

### 方案C（公式计算）
```javascript
usableBatteryCapacity = Math.min(dailyEnergyToShiftKwh / RTE, 50)
nominalBatteryCapacity = usableBatteryCapacity / DoD
```

**优势**：
- 基于实际发电量和目标自用率计算
- 0.44kW系统计算出0.43kWh电池
- 电池容量与系统规模匹配

## 解决方案建议

### 短期方案（数据层面）

1. **标记不经济配置**
   ```
   添加字段：经济性评级
   - 优秀：IRR > 10%
   - 良好：IRR 5-10%
   - 一般：IRR 0-5%
   - 不推荐：IRR < 0% 或 N/A
   ```

2. **筛选输出**
   ```
   仅输出经济性评级为"一般"及以上的配置
   或单独输出不推荐配置清单
   ```

3. **添加警告信息**
   ```
   对于N/A记录，添加原因说明：
   "投资成本过高，20年内无法回本"
   ```

### 中期方案（Quote计算层面）

1. **优化功率映射表**
   ```javascript
   // 为小系统添加更小的电池选项
   { min: 0, max: 2, nominal_battery_capacity_kwh: 5.0, inverter_kw: 3 }
   { min: 2, max: 5, nominal_battery_capacity_kwh: 10.0, inverter_kw: 5 }
   { min: 5, max: 10, nominal_battery_capacity_kwh: 15.0, inverter_kw: 8 }
   ```

2. **添加经济性检查**
   ```javascript
   // 在Quote计算时检查电池成本占比
   if (batteryCost / totalCost > 0.7) {
       result.warning = "电池配置可能不经济";
   }
   ```

3. **动态电池容量**
   ```javascript
   // 根据系统规模动态调整电池容量
   const maxEconomicBattery = systemPower * 3; // 不超过光伏容量的3倍
   batteryCapacity = Math.min(mappedCapacity, maxEconomicBattery);
   ```

### 长期方案（产品设计层面）

1. **引入电池容量优化算法**
   - 基于IRR最大化选择最优电池容量
   - 考虑用户用电模式和电价

2. **分级推荐系统**
   - 根据系统规模推荐合适的方案
   - 小系统（<5kW）：推荐方案C或无电池
   - 中型系统（5-15kW）：推荐方案B或C
   - 大型系统（>15kW）：推荐方案A或B

3. **用户定制化**
   - 允许用户自定义电池容量
   - 实时显示经济性指标（IRR、回本周期）

## 实际应用建议

### 对于销售人员

1. **避免推荐N/A配置**
   - 这些配置在经济上不可行
   - 客户投资后会后悔

2. **重点推荐方案C**
   - 对于小系统，方案C最经济
   - IRR通常在15-35%之间

3. **中大型系统可选A/B**
   - 10kW以上系统，方案A/B开始有经济性
   - 需要根据具体情况比较IRR

### 对于客户

1. **小系统用户**
   - 如果只能装<10块面板，选择方案C
   - 或考虑不装电池，仅装光伏

2. **预算有限用户**
   - 优先考虑IRR高的方案
   - 不要被大电池容量吸引

3. **长期投资用户**
   - 关注贴现回本周期
   - 确保在10年内回本

## 结论

1. **N/A不是错误，是真实反映**
   - 这些配置确实无法在20年内回本
   - 计算逻辑正确，结果可信

2. **问题在于配置设计**
   - 功率映射表不适合小系统
   - 需要优化电池容量分配逻辑

3. **方案C是小系统最优选择**
   - 基于公式计算，电池容量合理
   - IRR高，回本快

4. **建议改进Quote系统**
   - 优化功率映射表
   - 添加经济性检查
   - 标记不推荐配置
