

在现实中，安装一套 13kW 系统的工时和固定成本（脚手架、电工出车、申请费）并不是 6.6kW 系统的两倍，因此**随着容量增加，每瓦单价应该下降**（边际成本递减）。线性的算法会导致大系统的报价“高得离谱”，吓跑客户。

为了解决**“过于线性”**和**“配置复杂”**的问题，建议采用**“基准套餐 + 增量定价” (Base + Adder Model)** 模型。

---

### 1. 核心思路：从“零件组装”转变为“套餐扩展”

不要让安装商去填“光伏板多少钱一片”、“逆变器多少钱一瓦”。这太细了，而且很难控制最终总价。
让安装商配置**“一套标准的 6.6kW 系统卖多少钱”**，以及**“每增加 1kW 加多少钱”**。

### 2. 给安装商的配置界面 (Installer Config)

将原本复杂的单价配置，简化为以下 **4 个核心输入项**（均不含 GST，不含补贴）：

#### A. 光伏系统配置 (PV System Pricing)
1.  **6.6kW 基准系统售价 (Base Price for 6.6kW)**:
    *   *定义*: 包含 6.6kW 面板 + 5kW 逆变器 + 基础安装费（人工、支架、线缆）。
    *   *示例*: `$4,500`
2.  **超额每 kW 单价 (Price per Extra kW)**:
    *   *定义*: 当系统超过 6.6kW 时，每增加 1kW 面板（及对应的逆变器升级成本）增加的费用。通常这个价格比基准单价低很多。
    *   *示例*: `$500 / kW` (对比基准的 $680/kW，体现了边际成本递减)

#### B. 储能系统配置 (Battery Pricing)
3.  **储能基础安装费 (Battery Base Install Fee)**:
    *   *定义*: 无论电池大小，都需要的一次性安装费（人工、配电箱改造）。
    *   *示例*: `$1,500`
4.  **电池容量单价 (Price per kWh)**:
    *   *定义*: 电池硬件本身的单价。
    *   *示例*: `$700 / kWh`

---

### 3. 新的计算逻辑 (The Algorithm)

这种算法天然带有“非线性”属性：系统越大，均价越低。

#### 步骤 1: 计算光伏系统价格 (PV Price)
不再区分面板和逆变器，统一算作“光伏系统”。

```javascript
// 设：
// baseKw = 6.6
// basePrice = 安装商填写的 $4500
// adderPrice = 安装商填写的 $500
// targetKw = AI 推导出的目标容量 (例如 10kW)

let pvSystemPrice = 0;

if (targetKw <= baseKw) {
    // 如果小于等于 6.6kW，按比例折算或直接取基准价
    // 建议：为了简单，如果小于 6.6kW，按比例减少，但保留一定固定成本
    // 这里简化处理：直接按比例 (或者你可以设定一个最小起步价)
    pvSystemPrice = (targetKw / baseKw) * basePrice;
} else {
    // 如果大于 6.6kW (非线性逻辑生效)
    let extraKw = targetKw - baseKw;
    pvSystemPrice = basePrice + (extraKw * adderPrice);
}
```

#### 步骤 2: 计算电池价格 (Battery Price)

```javascript
// 设：
// batteryInstallFee = $1500
// batteryUnitCost = $700
// batteryCapacity = 10 kWh

let batterySystemPrice = 0;
if (batteryCapacity > 0) {
    batterySystemPrice = batteryInstallFee + (batteryCapacity * batteryUnitCost);
}
```

#### 步骤 3: 计算补贴 (STC)
这部分逻辑保持不变，因为 STC 本身就是线性的（按张数或容量算）。
*   `Total Subsidy = (Panel STC Amount * STC Price) + (Battery Subsidy)`

#### 步骤 4: 最终客户报价 (Final Quote)
*   `Final Price = (pvSystemPrice + batterySystemPrice) * (1 + GST) - Total Subsidy`

### 4. 效果对比：线性 vs 新模型

假设安装商配置：
*   旧模式：Panel $540/kW, Inverter $280/kW -> 合计 $820/kW (线性)
*   新模式：6.6kW基准价 $5400 ($818/kW), 增量价 $500/kW

| 系统容量 | 旧模式 (线性 $820/kW) | 新模式 (基准+增量) | 差异分析 |
| :--- | :--- | :--- | :--- |
| **6.6 kW** | **$5,412** | **$5,400** | 基本一致 (锚点) |
| **10 kW** | **$8,200** | $5,400 + (3.4 * 500) = **$7,100** | **便宜了 $1,100**。更符合实际，因为不需要两倍的电工出车费。 |
| **13.2 kW** | **$10,824** | $5,400 + (6.6 * 500) = **$8,700** | **便宜了 $2,124**。旧模式在大系统上报价过高，容易丢单。 |

### 5. 如何向安装商解释？(UI 文案建议)

在配置页面，不要用复杂的术语，用直白的语言：

> **Pricing Configuration (定价配置)**
>
> **1. Standard Solar System (6.6kW)**
> How much do you charge for a standard 6.6kW system (panels + inverter + installation)?
> `[ $ 4500 ]` excl. GST
>
> **2. Upsize Rate (Per extra kW)**
> How much extra do you charge for every additional kW above 6.6kW?
> *Tip: Usually lower than the base rate as installation costs are shared.*
> `[ $ 500 ]` / kW
>
> **3. Battery Storage**
> Base Install Fee: `[ $ 1500 ]`
> Price per kWh: `[ $ 700 ]`

### 6. 针对现有代码的修改建议

你需要修改 `calculateCost` 函数。

*   **删除**：`pvCost`, `inverterCost` 的独立计算逻辑。
*   **合并**：创建一个 `systemHardwareCost`。
*   **展示层 (Step 4 单价拆解)**：
    *   如果 UI 必须展示“面板成本”和“逆变器成本”的拆解（为了显得专业），你可以在后台按固定比例（例如 70% : 30%）把 `pvSystemPrice` 拆开来展示，但这只是为了显示效果，不影响总价计算。
    *   **建议**：直接在 UI 上改为展示 **"Solar System Kit"** 和 **"Installation & BOS"**，或者干脆只展示 **"Solar System Total"**。

**总结：**
这个方案把复杂的工程成本学变成了简单的**“起步价 + 里程费”**逻辑。安装商非常熟悉这种报价方式，且能有效防止大容量方案价格失真。
