# 储能容量计算方法对比分析

## 1. 现有方法分析

### 1.1 现有算法代码

```javascript
function calculateBatteryCapacity(pvSystemKw, state, method = 'balanced') {
    const annualConsumption = STATE_CONSUMPTION[state];
    const dailyConsumption = annualConsumption / 365;
    
    // 计算傍晚高峰用电 (17:00-21:00, 索引 16-20)
    const hourlyProfile = STATE_HOURLY_PROFILE[state];
    const eveningPeakRatio = (hourlyProfile[16] + hourlyProfile[17] + hourlyProfile[18] + hourlyProfile[19] + hourlyProfile[20]) / 100;
    const eveningPeakConsumption = dailyConsumption * eveningPeakRatio;
    
    // 三种方案的系数
    // economy:  { daily: 0.2, evening: 1.0, pv: 0.8 }
    // balanced: { daily: 0.3, evening: 1.5, pv: 1.0 }
    // premium:  { daily: 0.5, evening: 2.0, pv: 1.5 }
    
    capacity = max(日用电×系数, 傍晚峰×系数, PV容量×系数)
}
```

### 1.2 现有方法的特点

| 特点 | 说明 |
|------|------|
| ✅ 简单直观 | 三个维度取最大值 |
| ✅ 考虑了用电模式 | 使用各州小时用电比例 |
| ❌ 未考虑 RTE/DOD | 计算的是需求能量，不是电池额定容量 |
| ❌ 未考虑光伏剩余 | 直接用 PV 容量，而非实际可储存的剩余光伏 |
| ❌ 未考虑功率需求 | 只计算能量，没有考虑充放电功率 |
| ❌ 方案差异化不够明显 | 仅通过系数调整，缺乏场景化设计 |

## 2. 用户提出的新方法分析

### 2.1 方法A：基于不同目标场景权重

```python
def calculate_battery_size(
    daily_energy_consumption,      # 日总用电量 kWh
    evening_peak_power,            # 晚间峰值功率 kW
    evening_peak_hours,            # 晚间峰值时长 h
    daily_pv_generation,           # 光伏日发电量 kWh
    daytime_consumption_ratio,     # 白天用电占比 (0-1)
    plan_type,                     # 'conservative' | 'balanced' | 'premium'
    RTE=0.9,
    DOD=0.8
):
    # 1. 计算光伏剩余能量
    daytime_consumption = daily_energy_consumption * daytime_consumption_ratio
    surplus_pv = max(0, daily_pv_generation - daytime_consumption)
    
    # 2. 计算晚间峰值需求能量
    evening_peak_energy = evening_peak_power * evening_peak_hours
    
    # 3. 差异化策略
    if plan_type == 'conservative':
        target_energy = evening_peak_energy * 0.7
        safety_factor = 1.1
    elif plan_type == 'balanced':
        target_energy = min(evening_peak_energy * 1.0, surplus_pv * 0.8)
        safety_factor = 1.2
    elif plan_type == 'premium':
        target_energy = max(evening_peak_energy * 1.2, surplus_pv * 0.95, daily_energy_consumption * 0.5)
        safety_factor = 1.4
    
    # 4. 计算电池额定容量
    battery_size = (target_energy * safety_factor) / (RTE * DOD)
```

### 2.2 方法A的特点

| 特点 | 说明 |
|------|------|
| ✅ 考虑 RTE/DOD | 正确转换为电池额定容量 |
| ✅ 计算光伏剩余 | 考虑白天自消纳后的剩余光伏 |
| ✅ 场景化设计 | 不同方案有不同的目标场景 |
| ✅ 安全系数 | 考虑实际使用中的冗余 |
| ⚠️ 需要更多输入参数 | 需要晚间峰值功率、白天用电占比等 |

### 2.3 方法B：屋顶受限时的差异化策略

当 PV 容量相同时，通过调整电池策略实现差异化：

```python
def differentiate_battery_when_same_pv(fixed_pv_capacity, ...):
```

## 5. 分析与建议

### 5.1 现有方法的优缺点

**优点**：
1. 简单易懂，计算快速
2. 电池容量随 PV 容量线性增长，符合直觉
3. 三套方案差异明显但不极端

**缺点**：
1. **未考虑 RTE/DOD**：实际需要的电池容量应该更大
2. **PV 系数过于简单**：没有考虑实际的光伏剩余能量
3. **缺乏场景化设计**：三套方案只是系数不同，没有体现不同的使用场景

### 5.2 新方法的优缺点

**方法A优点**：
1. 考虑了 RTE/DOD，计算更准确
2. 计算了实际的光伏剩余能量
3. 场景化设计更清晰

**方法A缺点**：
1. **premium 方案结果过大**：当光伏剩余能量很高时，电池容量需求激增
2. **需要更多输入参数**：晚间峰值功率、白天用电占比等难以准确获取
3. **balanced 方案使用 min() 可能导致结果偏小**

**方法B优点**：
1. 专门针对屋顶受限场景设计
2. 结果相对合理，不会过大

**方法B缺点**：
1. 假设参数（60%剩余）可能不准确
2. 仅适用于 PV 容量固定的场景

### 5.3 改进建议

#### 建议1：混合方法（推荐）

结合现有方法的简单性和新方法的准确性：

```javascript
function calculateBatteryCapacity_v2(pvSystemKw, state, method) {

    const eveningPeakConsumption = dailyConsumption * eveningPeakRatio;

    const dailyPvGeneration = pvSystemKw * 4.5;  // 假设日照4.5小时
    const daytimeRatio = 0.4;  // 白天用电占比
    const surplusPv = Math.max(0, dailyPvGeneration - dailyConsumption * daytimeRatio);

    const DOD = 0.8;

        // 平衡型：晚间峰值 vs 光伏剩余的30%，取较小值

            eveningPeakConsumption * 1.2,
            surplusPv * 0.3
        );
        // 但至少要覆盖晚间峰值
        targetEnergy = Math.max(targetEnergy, eveningPeakConsumption);
        safetyFactor = 1.2;

        // 高端型：晚间峰值 + 部分光伏剩余 + 备用

            eveningPeakConsumption * 1.5,
            surplusPv * 0.5,
            dailyConsumption * 0.3  // 30%日用电备用
        );
        // 设置上限，避免过大
        targetEnergy = Math.min(targetEnergy, dailyConsumption * 0.8);
        safetyFactor = 1.3;
    }
    
    // 计算电池额定容量
    const batteryCapacity = (targetEnergy * safetyFactor) / efficiency;
    
    return batteryCapacity;
}
```

## 7. 改进方案：基于光伏剩余能量的计算方法

### 7.1 核心思路

将原有的 `PV容量×系数` 替换为 `光伏剩余能量×系数`，更准确地反映实际可储存的能量。

### 7.2 光伏剩余能量计算

```javascript
/**
 * 计算光伏剩余能量
 * @param {number} pvSystemKw - 光伏系统容量 (kW)
 * @param {number} dailyConsumption - 日用电量 (kWh)
 * @param {string} state - 州代码
 * @returns {object} 光伏发电和剩余能量信息
 */
function calculatePvSurplus(pvSystemKw, dailyConsumption, state) {
    // 1. 计算光伏日发电量
    // 使用各州的峰值日照时数 (PSH)
    const STATE_PSH = {
        'NSW': 4.5,   // 悉尼
        'VIC': 4.2,   // 墨尔本
        'QLD': 5.0,   // 布里斯班
        'SA': 4.8,    // 阿德莱德
        'WA': 5.2,    // 珀斯
        'TAS': 3.8,   // 霍巴特
        'ACT': 4.5,   // 堪培拉
        'NT': 5.5     // 达尔文
    };
    
    const psh = STATE_PSH[state] || 4.5;
    const systemLoss = 0.85;  // 系统损耗系数 (逆变器效率、线损、灰尘等)
    const dailyPvGeneration = pvSystemKw * psh * systemLoss;
    
    // 2. 计算白天用电量
    // 使用各州的小时用电比例，计算 6:00-18:00 的用电占比
    const hourlyProfile = STATE_HOURLY_PROFILE[state];
    let daytimeRatio = 0;
    for (let h = 6; h <= 17; h++) {
        daytimeRatio += hourlyProfile[h];
    }
    daytimeRatio /= 100;  // 转换为小数
    
    const daytimeConsumption = dailyConsumption * daytimeRatio;
    
    // 3. 计算光伏自消纳和剩余
    // 假设白天用电的 70% 可以直接使用光伏（负载与发电时间重叠）
    const selfConsumption = Math.min(daytimeConsumption * 0.7, dailyPvGeneration);
    const surplusPv = Math.max(0, dailyPvGeneration - selfConsumption);
    
    return {
        dailyPvGeneration,      // 光伏日发电量
        daytimeConsumption,     // 白天用电量
        daytimeRatio,           // 白天用电占比
        selfConsumption,        // 光伏自消纳量
        surplusPv,              // 光伏剩余能量
        surplusRatio: dailyPvGeneration > 0 ? surplusPv / dailyPvGeneration : 0  // 剩余比例
    };
}
```

### 7.3 改进的电池容量计算算法

```javascript
/**
 * 改进的电池容量计算 - 基于光伏剩余能量
 * @param {number} pvSystemKw - 光伏系统容量 (kW)
 * @param {string} state - 州代码
 * @param {string} method - 方案类型: 'economy' | 'balanced' | 'premium'
 * @returns {object} 电池容量推荐
 */
function calculateBatteryCapacity_v2(pvSystemKw, state, method = 'balanced') {
    const annualConsumption = STATE_CONSUMPTION[state];
    const dailyConsumption = annualConsumption / 365;
    
    // 1. 计算傍晚高峰用电 (17:00-21:00)
    const hourlyProfile = STATE_HOURLY_PROFILE[state];
    const eveningPeakRatio = (hourlyProfile[16] + hourlyProfile[17] + 
                              hourlyProfile[18] + hourlyProfile[19] + 
                              hourlyProfile[20]) / 100;
    const eveningPeakConsumption = dailyConsumption * eveningPeakRatio;
    
    // 2. 计算光伏剩余能量
    const pvSurplus = calculatePvSurplus(pvSystemKw, dailyConsumption, state);
    const surplusPv = pvSurplus.surplusPv;
    
    // 3. 效率参数
    const RTE = CONFIG.battery.rte || 0.95;
    const DOD = CONFIG.battery.dod || 0.9;
    const efficiency = RTE * DOD;  // 约 0.855
    
    // 4. 根据方案计算目标能量
    let targetEnergy = 0;
    let methodDesc = '';
    
    if (method === 'economy') {
        // 经济型：覆盖晚间峰值的 80%，或存储光伏剩余的 40%
        const method1 = dailyConsumption * 0.2;           // 20% 日用电
        const method2 = eveningPeakConsumption * 0.8;     // 80% 傍晚峰值
        const method3 = surplusPv * 0.4;                  // 40% 光伏剩余
        targetEnergy = Math.max(method1, method2, method3);
        methodDesc = `max(日用电×20%=${method1.toFixed(1)}, 傍晚峰×0.8=${method2.toFixed(1)}, 光伏剩余×0.4=${method3.toFixed(1)})`;
        
    } else if (method === 'balanced') {
        // 平衡型：完全覆盖晚间峰值，或存储光伏剩余的 60%
        const method1 = dailyConsumption * 0.3;           // 30% 日用电
        const method2 = eveningPeakConsumption * 1.2;     // 120% 傍晚峰值
        const method3 = surplusPv * 0.6;                  // 60% 光伏剩余
        targetEnergy = Math.max(method1, method2, method3);
        methodDesc = `max(日用电×30%=${method1.toFixed(1)}, 傍晚峰×1.2=${method2.toFixed(1)}, 光伏剩余×0.6=${method3.toFixed(1)})`;
        
    } else if (method === 'premium') {
        // 高端型：最大化光伏自消纳 + 备用能力
        const method1 = dailyConsumption * 0.5;           // 50% 日用电 (半天备用)
        const method2 = eveningPeakConsumption * 1.5;     // 150% 傍晚峰值
        const method3 = surplusPv * 0.85;                 // 85% 光伏剩余
        targetEnergy = Math.max(method1, method2, method3);
        methodDesc = `max(日用电×50%=${method1.toFixed(1)}, 傍晚峰×1.5=${method2.toFixed(1)}, 光伏剩余×0.85=${method3.toFixed(1)})`;
    }
    
    // 5. 计算电池额定容量 (考虑效率)
    let capacity = targetEnergy / efficiency;
    
    // 6. 设置容量上下限
    const MIN_CAPACITY = 5;    // 最小 5 kWh
    const MAX_CAPACITY = 50;   // 最大 50 kWh
    capacity = Math.max(MIN_CAPACITY, Math.min(MAX_CAPACITY, capacity));
    
    // 7. 标准化到常见电池规格
    let finalCapacity = capacity;
    if (CONFIG.battery.useStandards) {
        const standardSizes = [5, 6.5, 9.6, 10, 13.5, 16, 20, 25, 30, 40, 50];
        finalCapacity = standardSizes.find(s => s >= capacity) || MAX_CAPACITY;
    }
    
    return {
        calculated: capacity,
        standard: finalCapacity,
        isStandardized: CONFIG.battery.useStandards,
        methodDesc: methodDesc,
        dailyConsumption: dailyConsumption,
        eveningPeak: eveningPeakConsumption,
        pvSurplus: pvSurplus,
        targetEnergy: targetEnergy,
        efficiency: efficiency
    };
}
```

### 7.6 新方法的优势

1. **更准确反映实际需求**：基于光伏剩余能量，而非简单的 PV 容量
2. **考虑了效率损失**：RTE × DOD 修正
3. **有合理的容量上限**：最大 50 kWh，避免过度推荐
4. **差异化更明显**：三套方案的容量差异更大，更能体现不同定位
5. **考虑了地区差异**：使用各州的峰值日照时数 (PSH)
