# V4 版本：完整计算逻辑与公式说明

> 目录位置：`1127 计算规则/page/V4/page/docs/V3_计算逻辑与公式说明.md`（文件名沿用历史命名，内容为 V4）

本文档以 **V4 实际页面代码** 为准，覆盖从“屋顶数据 → 光伏容量 → 逆变器 → 储能电池 → 成本与补贴 → 页面输出”的全链路计算逻辑、公式、以及默认预设参数，并给出关键原理解释。

---

## 1. 范围与目标

- **范围**
  - 屋顶坡面评分与组件分配（满铺/目标 kW）
  - 逆变器选型与容配比约束（目标容配比、最大容配比）
  - **V4 电池容量推导（基于 6 月逐小时 PV-Load 剩余）**
  - 成本计算（A/B/C/D 方案实现中主要使用 A/B）
  - 补贴计算（STC：PV + Battery）
  - 三套方案卡片展示与推导日志展示

- **目标**
  - 在统一的预设数据与配置下，给出更符合“6 月逐小时可储存能量（PV-Load 剩余）”的电池容量推荐，并实现 A/B/C 清晰的产品定位：
    - C：削峰
    - B：削峰 + 移峰/套利/VPP
    - A：整夜覆盖 + 更强移峰（并受 50kWh 补贴上限约束）

## 3. 全局预设参数（默认值）

### 3.1 PV 参数（`DEFAULT_CONFIG.pv`）

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `pv.pmax` | 440 W | 单块组件额定功率 |
| `pv.annualKwhPerKw` | 1526 kWh/kW/yr | 年发电系数兜底（当没有州系数时回退） |
| `pv.annualYieldByState` | 见配置 | **各州年发电系数**（kWh/kW/yr） |

> V4 优先使用 `pv.annualYieldByState[state]`，若缺失则回退到 `pv.annualKwhPerKw`。

### 3.2 电池推导参数（`DEFAULT_CONFIG.battery`）

#### 3.2.1 三套方案系数（V4：6月逐小时剩余）

V4 只保留少量可解释且可配置的系数：

| 配置键 | 默认值 | 含义 |
|---|---:|---|
| `battery.v4.aSurplus` | 0.8 | A 方案：`kA × E_surplus` 中的 `kA` |
| `battery.v4.bSurplus` | 0.5 | B 方案：`kB × E_surplus` 中的 `kB` |

> 注：C 方案不使用 `E_surplus` 系数，目标能量固定为晚高峰用电。

#### 3.2.2 效率参数

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `battery.rte` | 0.95 | 往返效率（Round Trip Efficiency） |
| `battery.dod` | 0.9 | 放电深度（Depth of Discharge） |

- **组合效率**：
  - `efficiency = rte × dod = 0.95 × 0.9 = 0.855`

#### 3.2.3 容量限制与标准化

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `battery.minCapacity` | 5 kWh | 最小推荐容量 |
| `battery.maxCapacity` | 50 kWh | 最大推荐容量 |
| `battery.useStandards` | true | 是否使用标准规格向上取整 |
| `battery.standards` | `[5, 6.5, 9.6, 10, 13.5, 16, 20, 25, 30, 40, 50]` | 标准电池容量集合 |

#### 3.2.4 V4：月/小时分布兜底数据

V4 的电池推导使用以下兜底数据构造 6 月逐小时曲线：

- 发电月占比（`PV_MONTHLY_SHARE`）：来自 `兜底用的小时发电量比例.md`
- 发电小时占比（`PV_HOURLY_SHARE`）：来自 `兜底用的小时发电量比例.md`
- 用电月占比（`LOAD_MONTHLY_SHARE`）：来自 `各州月用电比例.md`
- 用电小时占比（`STATE_HOURLY_PROFILE`）：来自 `各州各时段用电比例.md`

## 4. 输入数据结构

### 4.1 屋顶坡面数据（House）

页面内部将坡面数据解析为对象数组，每个坡面包含：

- `id`：坡面编号
- `aspect`：方位角（°）
- `max`：该坡面最多可安装组件数量（面板数）
- `score`：由方位角计算的发电潜力评分（越大越优）

### 4.2 用户选择输入

- `houseId`：房屋 ID
- `phaseType`：电网类型（单相/三相）
- `state`：州（用于用电量、补贴系数、日照等预设）

---

## 5. 计算流程总览（数据流）

1. 读取配置：`CONFIG = loadConfig()`
2. 解析房屋坡面：`parseHouseData()`
3. 进入推导引擎：`generateProposalsWithDerivation(houseId, phaseType)`
4. 对坡面评分并排序（方位角 → score）
5. 计算屋顶物理上限（可装总面板数 → 最大 kW）
6. 逐方案：
   - 选目标 kW（premium/balanced/economy）
   - `fillRoofWithLog(...)`：按坡面优先级分配组件数，得到方案 PV(kW)
   - 逆变器选型：`selectInverterForPlan(...)` 并校验容配比
   - **电池容量推导（V3）**：`calculateBatteryCapacity(pvKw, state, plan)`
7. 成本与补贴计算：
   - `calculateCostBothSchemes(pvKw, invKw, batteryKwh, state)`
   - `calculateSubsidy(pvKw, batteryNominalKwh, state)`
8. 输出到 UI：
   - 推导日志：`renderDerivationSteps(derivationLog)`
   - 卡片：`updateCard('propA'|'propB'|'propC', planData)`

## 6. 屋顶坡面评分与方向（原理+公式）

### 6.1 方向判定

依据 `aspect`（方位角）区间映射到 N/NE/E/...（用于展示与分配日志）。

### 6.2 坡面评分 `calculateSlopeScore(aspect)`

**原理**：南半球北向（0°/360°）发电最佳，偏离北向越多评分越低。

- 计算与北向偏差：
  - `deviation = min(|aspect-0|, 360-|aspect-0|)`
- 分段评分（代码实现为线性映射）：
  - 偏差 `<=45°`：约 90~100
  - 偏差 `45~135°`：约 70~90
  - 偏差 `>135°`：最低约 40

评分用于 **组件分配时的贪心排序**：优先把组件铺在评分更高的坡面。

---

## 7. 组件分配：从目标 kW 到面板数量（`fillRoofWithLog`）

### 7.1 目标面板数

- `neededPanels = ceil(targetKw × 1000 / panelWatt)`
- 其中 `panelWatt = AppData.pv.pmax`（默认 440W）

### 7.2 分配逻辑（贪心）

- 按坡面评分从高到低遍历
- 每个坡面最多放 `max` 片
- 直到满足 `neededPanels` 或可用坡面耗尽

### 7.3 输出

- `count`：总安装面板数
- `totalKw`：
  - `totalKw = count × panelWatt / 1000`
- `layoutStr`：分配摘要（用于展示）

---

## 8. 逆变器选型与容配比（原理+公式）

### 8.1 核心指标：容配比

- `ratio = PV_kW / Inverter_kW`
- 页面用于展示百分比：`ratioPercent = PV_kW / Inverter_kW × 100%`

### 8.2 目标容配比与上限

- `TARGET_RATIO = inverter.targetRatio / 100`（默认 1.8）
- `MAX_RATIO = inverter.maxRatio / 100`（默认 2.0）

### 8.3 逆变器需求功率

- `rawInvRequirement = PV_kW / TARGET_RATIO`

### 8.4 逆变器规格选择

- 受电网类型上限约束：
  - 单相：`<= singleMaxKw`
  - 三相：`<= threeMaxKw`
- 若启用可选规格列表，则从列表中选 >= required 的最小值；否则按上限/取整规则。

### 8.5 若超过最大容配比的处理

当 `PV_kW / Inverter_kW > MAX_RATIO`：

- 优先尝试 **提升逆变器** 到满足：
  - `Inverter_kW >= ceil(PV_kW / MAX_RATIO)`
- 若提升不可行（受上限/可选规格限制），则需要 **减少组件数**（在页面推导中有相应处理路径）。

## 9. V4 核心：电池容量推导（基于 6 月逐小时 PV-Load 剩余）

### 9.1 6月逐小时负载曲线

1. 年用电量：`Load_year = STATE_CONSUMPTION[state]`
2. 6月用电量：`Load_june = Load_year × load_month_share[state][June]`
3. 6月日均用电：`Load_day = Load_june / 30`
4. 逐小时用电：`Load_hour[h] = Load_day × load_hour_share[state][h]`

得到两段用电能量：

- 晚高峰：`E_evening = Σ Load_hour[h]`，`h ∈ {17,18,19,20}`
- 整夜：`E_night = Σ Load_hour[h]`，`h ∈ {17..23,0..6}`

### 9.2 6月逐小时发电曲线

1. 年发电量：`PV_year = pv_kw × annual_yield[state]`
2. 6月发电量：`PV_june = PV_year × pv_month_share[June]`
3. 6月日均发电：`PV_day = PV_june / 30`
4. 逐小时发电：`PV_hour[h] = PV_day × pv_hour_share[h]`

### 9.3 6月日均光伏剩余（逐小时截断后累加）

- `E_surplus = Σ_h max(0, PV_hour[h] - Load_hour[h])`

> 注：V4 用“逐小时 PV-Load 截断累加”的方式得到可被储能吸收的能量，避免仅用日均与自消纳系数做近似。

### 9.4 三方案目标能量（E_req）

V4 保留 A/B/C 清晰的产品定位：

- **C（economy）削峰**：
  - `E_req_C = E_evening`
- **B（balanced）削峰 + 移峰/套利/VPP**：
  - `E_req_B = max(E_evening, kB × E_surplus)`
  - `kB = battery.v4.bSurplus`（默认 0.5）
- **A（premium）整夜覆盖 + 更强移峰**：
  - `E_req_A = max(E_night, kA × E_surplus)`
  - `kA = battery.v4.aSurplus`（默认 0.8）

### 9.5 考虑效率（RTE × DOD）得到额定容量

- `efficiency = rte × dod`
- `batteryRatedKwh = E_req / efficiency`

> 原理：
> - `targetEnergy` 是你希望“真正能拿出来用”的电量；
> - 电池标称容量要大于可用容量，需除以效率折损。

### 9.6 上下限与标准化（含补贴上限）

- 限制：
  - `batteryRatedKwh = clamp(batteryRatedKwh, minCapacity, maxCapacity)`
- 标准化（若开启）：
  - 从 `standards` 中选择 `>= batteryRatedKwh` 的最小值

## 10. 成本计算（A/B/C/D 方案）

页面实现了多种定价模型，常用为：

### 10.1 线性方案 A（`schemeA`）

- `pvCost = pvKw × pvPerKw`
- `inverterCost = inverterKw × inverterPerKw`
- `batteryCost = batteryKwh × batteryPerKwh`
- `preTaxTotal = pvCost + inverterCost + batteryCost`
- `taxTotal = preTaxTotal × (1 + gstRate)`

### 10.2 基准+增量方案 B（`schemeB`）

- PV：
  - `pvCost = basePrice + max(0, pvKw-baseKw) × adderPricePerKw`
- Battery：
  - `batteryCost = batteryInstallFee + batteryKwh × batteryPerKwh`
- 合计再加 GST

页面通过 `calculateCostBothSchemes` 同时计算 A 与 B（并展示）。

---

## 11. 补贴计算（STC：PV + Battery）

### 11.1 PV STC

- `deemingPeriod = deemingEndYear - installYear + 1`
- `pvStc = floor(pvKw × zoneRating[state] × deemingPeriod)`

### 11.2 Battery STC（按可用容量）

- 可用容量：`usable = batteryNominalKwh × dod`
- 上限：`cappedUsable = min(usable, batteryCapacityCap)`
- `batteryStc = floor(cappedUsable × batteryStcFactor)`

### 11.3 总补贴金额

- `totalStc = pvStc + batteryStc`
- `subsidyAmount = totalStc × stcPrice`

## 12. 输出与展示（卡片 + 推导日志）

### 12.1 三套方案卡片

每套方案 `planData` 包含：
- `totalKw`、`count`、`layoutStr`
- `inv`、`ratio`、`inverterDetail`
- `battery`：包含 `standard`、`methodDesc`、`pvSurplus`、`targetEnergy`、`efficiency` 等

卡片会展示：
- PV(kW)、面板数、逆变器、容配比
- **电池推荐容量（standard）**
- 价格与补贴

### 12.2 推导日志

`generateProposalsWithDerivation` 会生成详细步骤，包含：
- 坡面评分、物理上限
- 每套方案的组件分配
- 逆变器选型与容配比校验
- **电池推导（包含6月日均发电/用电、晚高峰、整夜、6月逐小时剩余、目标能量与效率换算）**

## 14. 建议的校验点（人工/测试）

- **电池推导稳定性**：
  - 任意房屋/任意州不应出现 `NaN`。
- **极端屋顶**：
  - `totalMaxPanels = 0` 时 PV 与电池应为 0 或最小值（按策略）并能正确展示。
- **极端 PV**：
  - 满铺大屋顶时 A/B 可能触达上限（默认 50kWh），并被标准化规格约束。

## 15. 术语表

- **容配比**：PV 装机容量 / 逆变器容量
- **RTE**：往返效率（充放电合计损耗）
- **DOD**：放电深度（可用容量占标称容量比例）
- **光伏剩余**：6月逐小时 `max(0, PV-Load)` 截断累加得到的日均可吸收能量
