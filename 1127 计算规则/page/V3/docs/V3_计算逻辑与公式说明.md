# V3 版本：完整计算逻辑与公式说明

> 目录位置：`1127 计算规则/page/V3/docs/V3_计算逻辑与公式说明.md`

本文档以 **V3 实际页面代码** 为准，覆盖从“屋顶数据 → 光伏容量 → 逆变器 → 储能电池 → 成本与补贴 → 页面输出”的全链路计算逻辑、公式、以及默认预设参数，并给出关键原理解释。

---

## 1. 范围与目标

- **范围**
  - 屋顶坡面评分与组件分配（满铺/目标 kW）
  - 逆变器选型与容配比约束（目标容配比、最大容配比）
  - **V3 电池容量推导（基于光伏剩余能量）**
  - 成本计算（A/B/C/D 方案实现中主要使用 A/B）
  - 补贴计算（STC：PV + Battery）
  - 三套方案卡片展示与推导日志展示

- **目标**
  - 在统一的预设数据与配置下，给出更符合“光伏实际可储存能量（光伏剩余）”的电池容量推荐，而不是仅使用“PV 装机容量”做线性推导。

---

## 3. 全局预设参数（默认值）

### 3.1 PV 参数（`DEFAULT_CONFIG.pv`）

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `pv.pmax` | 440 W | 单块组件额定功率 |
| `pv.annualKwhPerKw` | 1526 kWh/kW/yr | **年发电系数**（每 kW 装机年发电量） |

> V3 将发电量估算简化为统一系数：`日发电量 ≈ PV(kW) × 1526 / 365`。

### 3.2 电池推导参数（`DEFAULT_CONFIG.battery`）

#### 3.2.1 三套方案系数（V3：光伏剩余）

| 方案 | 日用电系数 `daily` | 傍晚峰系数 `evening` | 光伏剩余系数 `surplus` |
|---|---:|---:|---:|
| premium（高端型） | 0.5 | 1.5 | 0.85 |
| balanced（平衡型） | 0.3 | 1.2 | 0.6 |
| economy（经济型） | 0.2 | 0.8 | 0.4 |

#### 3.2.2 效率参数

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `battery.rte` | 0.95 | 往返效率（Round Trip Efficiency） |
| `battery.dod` | 0.9 | 放电深度（Depth of Discharge） |

- **组合效率**：
  - `efficiency = rte × dod = 0.95 × 0.9 = 0.855`

#### 3.2.3 容量限制与标准化

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `battery.minCapacity` | 5 kWh | 最小推荐容量 |
| `battery.maxCapacity` | 50 kWh | 最大推荐容量 |
| `battery.useStandards` | true | 是否使用标准规格向上取整 |
| `battery.standards` | `[5, 6.5, 9.6, 10, 13.5, 16, 20, 25, 30, 40, 50]` | 标准电池容量集合 |

#### 3.2.4 白天用电占比与自消纳系数（V3：用于光伏剩余）

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `battery.daytimeRatio[state]` | 见下表 | 白天用电占比（6:00-17:00） |
| `battery.selfConsumptionFactor` | 0.7 | 白天用电可被光伏直接覆盖的比例（时间重叠/负载匹配） |

白天用电占比默认表：

- NSW: 0.45
- VIC: 0.47
- QLD: 0.48
- SA: 0.44
- WA: 0.48
- TAS: 0.47
- ACT: 0.42
- NT: 0.48

### 3.3 逆变器参数（`DEFAULT_CONFIG.inverter`）

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `inverter.targetRatio` | 180 | 目标容配比（%） |
| `inverter.maxRatio` | 200 | 最大容配比（%） |
| `inverter.singleMaxKw` | 10 kW | 单相 Hybrid 最大功率 |
| `inverter.threeMaxKw` | 30 kW | 三相 Hybrid 最大功率 |

页面使用：
- `TARGET_RATIO = inverter.targetRatio / 100 = 1.8`
- `MAX_RATIO = inverter.maxRatio / 100 = 2.0`

### 3.4 方案目标容量参数（`DEFAULT_CONFIG.proposals`）

| 方案 | 默认值 | 含义 |
|---|---:|---|
| premium.targetKw | 999 | 满铺（无上限） |
| balanced.targetKwSmall | 10.0 kW | 小屋顶目标 |
| balanced.targetKwLarge | 13.0 kW | 大屋顶目标 |
| balanced.roofThreshold | 15 kW | 屋顶容量阈值 |
| economy.targetKw | 6.6 kW | 经济型目标 |

### 3.5 用电量预设（`DEFAULT_CONFIG.consumption`）

`STATE_CONSUMPTION[state]`：各州年用电量（kWh/yr），用于推导日用电量。

## 4. 输入数据结构

### 4.1 屋顶坡面数据（House）

页面内部将坡面数据解析为对象数组，每个坡面包含：

- `id`：坡面编号
- `aspect`：方位角（°）
- `max`：该坡面最多可安装组件数量（面板数）
- `score`：由方位角计算的发电潜力评分（越大越优）

### 4.2 用户选择输入

- `houseId`：房屋 ID
- `phaseType`：电网类型（单相/三相）
- `state`：州（用于用电量、补贴系数、日照等预设）

---

## 5. 计算流程总览（数据流）

1. 读取配置：`CONFIG = loadConfig()`
2. 解析房屋坡面：`parseHouseData()`
3. 进入推导引擎：`generateProposalsWithDerivation(houseId, phaseType)`
4. 对坡面评分并排序（方位角 → score）
5. 计算屋顶物理上限（可装总面板数 → 最大 kW）
6. 逐方案：
   - 选目标 kW（premium/balanced/economy）
   - `fillRoofWithLog(...)`：按坡面优先级分配组件数，得到方案 PV(kW)
   - 逆变器选型：`selectInverterForPlan(...)` 并校验容配比
   - **电池容量推导（V3）**：`calculateBatteryCapacity(pvKw, state, plan)`
7. 成本与补贴计算：
   - `calculateCostBothSchemes(pvKw, invKw, batteryKwh, state)`
   - `calculateSubsidy(pvKw, batteryNominalKwh, state)`
8. 输出到 UI：
   - 推导日志：`renderDerivationSteps(derivationLog)`
   - 卡片：`updateCard('propA'|'propB'|'propC', planData)`

## 6. 屋顶坡面评分与方向（原理+公式）

### 6.1 方向判定

依据 `aspect`（方位角）区间映射到 N/NE/E/...（用于展示与分配日志）。

### 6.2 坡面评分 `calculateSlopeScore(aspect)`

**原理**：南半球北向（0°/360°）发电最佳，偏离北向越多评分越低。

- 计算与北向偏差：
  - `deviation = min(|aspect-0|, 360-|aspect-0|)`
- 分段评分（代码实现为线性映射）：
  - 偏差 `<=45°`：约 90~100
  - 偏差 `45~135°`：约 70~90
  - 偏差 `>135°`：最低约 40

评分用于 **组件分配时的贪心排序**：优先把组件铺在评分更高的坡面。

---

## 7. 组件分配：从目标 kW 到面板数量（`fillRoofWithLog`）

### 7.1 目标面板数

- `neededPanels = ceil(targetKw × 1000 / panelWatt)`
- 其中 `panelWatt = AppData.pv.pmax`（默认 440W）

### 7.2 分配逻辑（贪心）

- 按坡面评分从高到低遍历
- 每个坡面最多放 `max` 片
- 直到满足 `neededPanels` 或可用坡面耗尽

### 7.3 输出

- `count`：总安装面板数
- `totalKw`：
  - `totalKw = count × panelWatt / 1000`
- `layoutStr`：分配摘要（用于展示）

---

## 8. 逆变器选型与容配比（原理+公式）

### 8.1 核心指标：容配比

- `ratio = PV_kW / Inverter_kW`
- 页面用于展示百分比：`ratioPercent = PV_kW / Inverter_kW × 100%`

### 8.2 目标容配比与上限

- `TARGET_RATIO = inverter.targetRatio / 100`（默认 1.8）
- `MAX_RATIO = inverter.maxRatio / 100`（默认 2.0）

### 8.3 逆变器需求功率

- `rawInvRequirement = PV_kW / TARGET_RATIO`

### 8.4 逆变器规格选择

- 受电网类型上限约束：
  - 单相：`<= singleMaxKw`
  - 三相：`<= threeMaxKw`
- 若启用可选规格列表，则从列表中选 >= required 的最小值；否则按上限/取整规则。

### 8.5 若超过最大容配比的处理

当 `PV_kW / Inverter_kW > MAX_RATIO`：

- 优先尝试 **提升逆变器** 到满足：
  - `Inverter_kW >= ceil(PV_kW / MAX_RATIO)`
- 若提升不可行（受上限/可选规格限制），则需要 **减少组件数**（在页面推导中有相应处理路径）。

## 9. V3 核心：电池容量推导（基于光伏剩余能量）

### 9.1 先算日用电量

- `dailyConsumption = annualConsumption / 365`
- `annualConsumption = STATE_CONSUMPTION[state]`

### 9.2 傍晚峰值用电（17:00-21:00）

- 使用 `STATE_HOURLY_PROFILE[state]`（%）
- `eveningPeakRatio = (h16+h17+h18+h19+h20)/100`
- `eveningPeakConsumption = dailyConsumption × eveningPeakRatio`

> 原理：电池的“晚高峰供电能力”是储能价值的主要体现，故单独建模。

### 9.3 光伏剩余能量（V3：`calculatePvSurplus`）

#### 9.3.1 日发电量（统一年发电系数）

- `dailyKwhPerKw = annualKwhPerKw / 365`
- `dailyPvGeneration = pvSystemKw × dailyKwhPerKw`

其中：
- `annualKwhPerKw = CONFIG.pv.annualKwhPerKw`（默认 1526）

#### 9.3.2 白天用电量

- `daytimeConsumption = dailyConsumption × daytimeRatio`
- `daytimeRatio = CONFIG.battery.daytimeRatio[state]`（默认见 3.2.4）

#### 9.3.3 白天自消纳（简化模型）

- `selfConsumption = min(daytimeConsumption × selfConsumptionFactor, dailyPvGeneration)`
- `selfConsumptionFactor = CONFIG.battery.selfConsumptionFactor`（默认 0.7）

#### 9.3.4 光伏剩余

- `surplusPv = max(0, dailyPvGeneration - selfConsumption)`

> 原理解释：
> - 电池能存的不是“PV 装机容量”，而是“白天发电中扣除即时消纳后的剩余”。
> - 该模型用 `daytimeRatio`+`selfConsumptionFactor` 将“负载与发电时间重叠”抽象成可配置参数。

### 9.4 三维度取最大值（目标能量）

对每个方案（premium/balanced/economy）取：

- 方法1（**日用电维度**）：
  - `E1 = dailyConsumption × coeff.daily`
- 方法2（**傍晚峰维度**）：
  - `E2 = eveningPeakConsumption × coeff.evening`
- 方法3（**光伏剩余维度**）：
  - `E3 = surplusPv × coeff.surplus`

- 目标能量：
  - `targetEnergy = max(E1, E2, E3)`

> 原理解释（为什么有日用电维度）：
> - 当 PV 很小/几乎无剩余时，仅靠 E3 会推荐 0；
> - 当晚高峰占比异常偏低时，仅靠 E2 会偏小；
> - E1 作为“基础保障下限”，让电池容量不至于过小，提升鲁棒性。

### 9.5 考虑效率（RTE × DOD）得到额定容量

- `efficiency = rte × dod`
- `batteryRatedKwh = targetEnergy / efficiency`

> 原理：
> - `targetEnergy` 是你希望“真正能拿出来用”的电量；
> - 电池标称容量要大于可用容量，需除以效率折损。

### 9.6 上下限与标准化

- 限制：
  - `batteryRatedKwh = clamp(batteryRatedKwh, minCapacity, maxCapacity)`
- 标准化（若开启）：
  - 从 `standards` 中选择 `>= batteryRatedKwh` 的最小值

## 10. 成本计算（A/B/C/D 方案）

页面实现了多种定价模型，常用为：

### 10.1 线性方案 A（`schemeA`）

- `pvCost = pvKw × pvPerKw`
- `inverterCost = inverterKw × inverterPerKw`
- `batteryCost = batteryKwh × batteryPerKwh`
- `preTaxTotal = pvCost + inverterCost + batteryCost`
- `taxTotal = preTaxTotal × (1 + gstRate)`

### 10.2 基准+增量方案 B（`schemeB`）

- PV：
  - `pvCost = basePrice + max(0, pvKw-baseKw) × adderPricePerKw`
- Battery：
  - `batteryCost = batteryInstallFee + batteryKwh × batteryPerKwh`
- 合计再加 GST

页面通过 `calculateCostBothSchemes` 同时计算 A 与 B（并展示）。

---

## 11. 补贴计算（STC：PV + Battery）

### 11.1 PV STC

- `deemingPeriod = deemingEndYear - installYear + 1`
- `pvStc = floor(pvKw × zoneRating[state] × deemingPeriod)`

### 11.2 Battery STC（按可用容量）

- 可用容量：`usable = batteryNominalKwh × dod`
- 上限：`cappedUsable = min(usable, batteryCapacityCap)`
- `batteryStc = floor(cappedUsable × batteryStcFactor)`

### 11.3 总补贴金额

- `totalStc = pvStc + batteryStc`
- `subsidyAmount = totalStc × stcPrice`

---

## 12. 输出与展示（卡片 + 推导日志）

### 12.1 三套方案卡片

每套方案 `planData` 包含：
- `totalKw`、`count`、`layoutStr`
- `inv`、`ratio`、`inverterDetail`
- `battery`：包含 `standard`、`methodDesc`、`pvSurplus`、`targetEnergy`、`efficiency` 等

卡片会展示：
- PV(kW)、面板数、逆变器、容配比
- **电池推荐容量（standard）**
- 价格与补贴

### 12.2 推导日志

`generateProposalsWithDerivation` 会生成详细步骤，包含：
- 坡面评分、物理上限
- 每套方案的组件分配
- 逆变器选型与容配比校验
- **电池推导（包含日发电、自消纳、剩余、目标能量与效率换算）**

## 13. 兼容性与鲁棒性（V3 特别说明）

### 13.1 兼容旧配置（V2 → V3）

- `config-loader.js` 在 `loadConfig()` 中对 `localStorage` 读到的配置做 **深合并**，确保 V3 新增字段缺失时自动回填默认值。
- `calculateBatteryCapacity` 额外做运行时兜底：
  - `surplus` 缺失时回退旧字段 `pv`，避免出现 `NaN`。

## 14. 建议的校验点（人工/测试）

- **电池推导稳定性**：
  - 任意房屋/任意州不应出现 `NaN`。
- **极端屋顶**：
  - `totalMaxPanels = 0` 时 PV 与电池应为 0 或最小值（按策略）并能正确展示。
- **极端 PV**：
  - 满铺大屋顶时电池应可触达上限（默认 50kWh），并被标准化规格约束。

---

## 15. 术语表

- **容配比**：PV 装机容量 / 逆变器容量
- **RTE**：往返效率（充放电合计损耗）
- **DOD**：放电深度（可用容量占标称容量比例）
- **光伏剩余**：日发电量扣除白天自消纳后的可储存电量
