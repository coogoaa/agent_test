## 概述

### 设计理念

本计算器采用**"以终为始"**的设计思路：
1. 先计算用户夜间缺多少电
2. 再配置电池容量
3. 再选择逆变器功率
4. 反推需要多少光伏板
5. 最后验证屋顶能否装得下

### 三种策略

| 策略 | 名称 | 电池容量系数 | 适用场景 |
|------|------|--------------|----------|
| A | 高端型 | 1.5 | 追求最大自给自足 |
| B | 平衡型 | 1.0 | 性价比最优 |
| C | 经济型 | 0.4 | 预算有限 |

## 计算流程

```
用户输入
  ↓
第1步：负载分析 (Load Analysis)
  ├─ 计算日均用电量
  ├─ 计算夜间用电量 (18:00-06:00)
  └─ 计算峰值功率
  ↓
第2步：电池定容 (Battery Sizing)
  ├─ 目标容量 = 夜间用电 × 策略系数
  ├─ 标准规格匹配（可选）
  └─ 选定电池容量
  ↓
第3步：逆变器选型 (Inverter Selection)
  ├─ 电池充放电需求 = 电池容量 × 0.5C
  ├─ 峰值负载覆盖 = 峰值功率 × 0.7
  ├─ 标准规格匹配（可选）
  └─ 选定逆变器功率
  ↓
第4步：光伏反推 (Target PV Sizing)
  ├─ 容配比选择（小电池1.5，大电池1.8）
  ├─ 目标光伏功率 = 逆变器功率 × 容配比
  └─ 目标面板数量 = 目标功率 / 单板功率
  ↓
第5步：物理校验与排布 (Physical Layout)
  ├─ 计算最小串联数 = 启动电压 / 面板电压
  ├─ 按效率排序屋顶坡面
  ├─ 依次分配面板到各坡面
  └─ 输出最终系统配置
  ↓
成本与补贴计算
  ├─ 硬件成本（面板+逆变器+电池）
  ├─ 税费计算（GST）
  ├─ STC补贴（光伏+电池）
  ├─ 州补贴（VIC/NSW）
  └─ 最终报价
```

## 五步计算详解

### 第1步：负载分析 (Load Analysis)

#### 目的
分析用户用电模式，计算夜间用电量和峰值功率

#### 计算公式

```javascript
// 1. 日均用电量
dailyAvgKwh = annual_usage_kwh / 365

// 2. 夜间用电量 (18:00-06:00，共12小时)
hourlyRatios = STATE_HOURLY_RATIOS[state]  // 24小时比例数组
nightRatioSum = sum(hourlyRatios[18:23]) + sum(hourlyRatios[0:5])
nightlyConsumptionKwh = dailyAvgKwh * nightRatioSum

// 3. 峰值功率
maxHourlyRatio = max(hourlyRatios)
peakPowerKw = dailyAvgKwh * maxHourlyRatio * 1.5  // 1.5为安全系数
```

#### 输出示例

```
年用电量: 8000 kWh
日均用电: 21.92 kWh/天
夜间比例: 45.23%
夜间用电: 9.91 kWh
峰值功率: 4.87 kW
```

---

### 第2步：电池定容 (Battery Sizing)

#### 目的
根据夜间用电量和策略系数，选择合适的电池容量

#### 计算逻辑

```javascript
function step2_sizeBattery(loadAnalysis, strategyType) {
    const nightlyLoad = loadAnalysis.nightlyConsumptionKwh;
    const ratio = STRATEGY_CONFIG[strategyType].battery_ratio;
    
    // 1. 计算目标容量
    const targetCapacity = nightlyLoad * ratio;
    
    // 2. 读取配置
    const matchStandard = config.battery.match_standard;
    const standardBatteries = config.battery.standard_capacities;
    
    let selectedBatteryKwh;
    
    if (matchStandard) {
        // 启用标准规格匹配
        // 选择最接近且不小于目标容量90%的标准规格
        selectedBatteryKwh = standardBatteries[0];
        for (let bat of standardBatteries) {
            if (bat >= targetCapacity * 0.9) {
                selectedBatteryKwh = bat;
                break;
            }
        }
        // 如果目标容量超过最大规格，选择最大规格
        if (targetCapacity > standardBatteries[standardBatteries.length - 1]) {
            selectedBatteryKwh = standardBatteries[standardBatteries.length - 1];
        }
    } else {
        // 不启用标准规格匹配：使用精确计算值
        selectedBatteryKwh = parseFloat(targetCapacity.toFixed(2));
    }
    
    return {
        targetCapacity,
        selectedBatteryKwh,
        ratio,
        matchStandard
    };
}
```

#### 策略对比

| 策略 | 夜间用电 | 系数 | 目标容量 | 标准匹配 | 精确值 |
|------|----------|------|----------|----------|--------|
| A-高端型 | 9.91 kWh | 1.5 | 14.87 kWh | 19.2 kWh | 14.87 kWh |
| B-平衡型 | 9.91 kWh | 1.0 | 9.91 kWh | 9.6 kWh | 9.91 kWh |
| C-经济型 | 9.91 kWh | 0.4 | 3.96 kWh | 5.0 kWh | 3.96 kWh |

### 第3步：逆变器选型 (Inverter Selection)

#### 目的
根据电池充放电需求和峰值负载，选择合适的逆变器功率

#### 计算逻辑

```javascript
function step3_selectInverter(batteryKwh, peakLoadKw) {
    // 1. 电池充放电需求 (0.5C倍率)
    const minInverterKwByBattery = batteryKwh * 0.5;
    
    // 2. 峰值负载覆盖 (70%覆盖率)
    const peakLoadCoverage = peakLoadKw * 0.7;
    
    // 3. 目标逆变器功率（取较大值）
    const targetInverterKw = Math.max(minInverterKwByBattery, peakLoadCoverage);
    
    // 4. 读取配置
    const matchStandard = config.inverter.match_standard;
    const maxSinglePhaseKw = config.inverter.max_single_phase_kw;
    
    let selectedInverterKw;
    
    if (matchStandard) {
        // 启用标准规格匹配
        const standardInverters = config.inverter.standard_powers;
        
        selectedInverterKw = standardInverters[0];
        for (let inv of standardInverters) {
            if (inv >= targetInverterKw) {
                selectedInverterKw = inv;
                break;
            }
        }
        
        // 单相上限限制
        if (selectedInverterKw > maxSinglePhaseKw) {
            selectedInverterKw = maxSinglePhaseKw;
        }
    } else {
        // 不启用标准规格匹配：使用精确计算值
        selectedInverterKw = Math.min(
            parseFloat(targetInverterKw.toFixed(2)), 
            maxSinglePhaseKw
        );
    }
    
    return {
        minInverterKwByBattery,
        targetInverterKw,
        selectedInverterKw,
        matchStandard
    };
}
```

#### 计算示例

```
电池容量: 9.6 kWh
充放电需求: 9.6 × 0.5 = 4.80 kW
峰值功率: 4.87 kW
峰值覆盖: 4.87 × 0.7 = 3.41 kW
目标功率: max(4.80, 3.41) = 4.80 kW

标准匹配: 5.0 kW (从 [3.0, 5.0, 6.0, 8.0, 10.0] 中选择)
精确值: 4.80 kW
```

### 第4步：光伏反推 (Target PV Sizing)

#### 目的
根据逆变器功率和容配比，反推需要的光伏板数量

#### 容配比 (DC/AC Ratio)

容配比是光伏直流功率与逆变器交流功率的比值，反映系统的配置策略：

| 电池容量 | 容配比 | 说明 |
|----------|--------|------|
| < 7 kWh | 1.5 | 小电池系统，适度超配 |
| ≥ 7 kWh | 1.8 | 大电池系统，澳洲黄金配置 |

**为什么要超配？**
- 光伏板实际输出受天气、温度、灰尘等影响
- 超配可以确保在非理想条件下仍能充分利用逆变器容量
- 1.8倍配比是澳洲市场经过验证的最优配置

#### 计算逻辑

```javascript
function step4_calculateTargetPV(inverterKw, batteryKwh, panelWatts) {
    // 1. 读取容配比配置
    const smallRatio = config.battery.small_ratio || 1.5;
    const largeRatio = config.battery.large_ratio || 1.8;
    
    // 2. 根据电池容量选择容配比
    const dcAcRatio = batteryKwh < 7.0 ? smallRatio : largeRatio;
    
    // 3. 计算目标光伏功率
    const targetDcKw = inverterKw * dcAcRatio;
    
    // 4. 计算目标面板数量（向上取整）
    const targetPanelCount = Math.ceil((targetDcKw * 1000) / panelWatts);
    
    return {
        targetDcKw,
        targetPanelCount,
        appliedRatio: dcAcRatio
    };
}
```

#### 计算示例

```
逆变器功率: 5.0 kW
电池容量: 9.6 kWh (≥7kWh)
容配比: 1.8 (澳洲黄金配置)
目标光伏功率: 5.0 × 1.8 = 9.0 kW
单板功率: 440 W
目标面板数: ceil(9000 / 440) = 21 块
```

### 第5步：物理校验与排布 (Physical Layout)

#### 目的
验证屋顶能否装下目标面板数，并进行实际排布

#### 约束条件

1. **电压约束**
   - 最小串联数 = 启动电压 / 面板工作电压
   - 最大串联数 = 最大电压 / 面板开路电压

2. **物理约束**
   - 每个坡面有最大面板数限制
   - 不足最小串联数的坡面将被移除

#### 计算逻辑

```javascript
function step5_physicalLayout(targetPanelCount, roofPlanes, panelSpecs, inverterSpecs) {
    // 1. 计算串联约束
    const minPanelsPerString = Math.ceil(inverterSpecs.v_start / panelSpecs.v_mp);
    const maxPanelsPerString = Math.floor(inverterSpecs.v_max / panelSpecs.v_oc);
    
    // 2. 按效率排序坡面（优先使用高效率坡面）
    const sortedPlanes = [...roofPlanes].sort((a, b) => b.efficiency - a.efficiency);
    
    let remainingPanelsToInstall = targetPanelCount;
    const installedPanelsPerPlane = {};
    const removedPlanes = [];
    
    // 3. 依次分配面板到各坡面
    for (let plane of sortedPlanes) {
        const planeId = plane.plane_id;
        const maxPanels = plane.max_panels;
        
        // 检查是否满足最小串联数
        if (maxPanels < minPanelsPerString) {
            removedPlanes.push({
                planeId,
                count: 0,
                reason: `不足最小串联数${minPanelsPerString}块`
            });
            installedPanelsPerPlane[planeId] = 0;
            continue;
        }
        
        // 计算该坡面可安装数量
        const canInstall = Math.min(remainingPanelsToInstall, maxPanels);
        
        // 检查是否满足最小串联数
        if (canInstall < minPanelsPerString) {
            installedPanelsPerPlane[planeId] = 0;
            continue;
        }
        
        installedPanelsPerPlane[planeId] = canInstall;
        remainingPanelsToInstall -= canInstall;
        
        if (remainingPanelsToInstall <= 0) break;
    }
    
    // 4. 计算最终系统参数
    const finalPanelCount = targetPanelCount - remainingPanelsToInstall;
    const finalSystemKw = (finalPanelCount * panelSpecs.watts) / 1000;
    
    return {
        layoutDetail: installedPanelsPerPlane,
        finalPanelCount,
        finalSystemKw,
        removedPlanes,
        minPanelsPerString,
        maxPanelsPerString
    };
}
```

#### 排布示例

```
目标面板数: 21 块
最小串联数: ceil(100V / 32V) = 4 块
最大串联数: floor(600V / 38.5V) = 15 块

屋顶坡面（按效率排序）:
  坡面A: 效率1.00, 最大10块 → 安装10块 ✅
  坡面B: 效率0.95, 最大8块  → 安装8块 ✅
  坡面C: 效率0.85, 最大6块  → 安装3块 ✅
  坡面D: 效率0.75, 最大2块  → 移除（不足4块）❌

最终系统: 21块面板, 9.24 kW
```

## 成本与补贴计算

### 硬件成本

```javascript
// 1. 光伏面板成本
panelCost = (finalPanelCount × panelWatts / 1000) × panel_price_per_kw
// 示例: (21 × 440 / 1000) × 1200 = $11,088

// 2. 逆变器成本
inverterCost = selectedInverterKw × inverter_price_per_kw
// 示例: 5.0 × 280 = $1,400

// 3. 电池成本
batteryCost = selectedBatteryKwh × battery_price_per_kwh
// 示例: 9.6 × 865 = $8,304

// 4. 税前总价
preTaxTotal = panelCost + inverterCost + batteryCost
// 示例: $20,792

// 5. GST (10%)
gst = preTaxTotal × gst_rate
// 示例: $2,079

// 6. 含税报价
totalWithGst = preTaxTotal + gst
// 示例: $22,871
```

### STC补贴计算

#### 光伏STC补贴

```javascript
// 1. 计算STC数量
pvStcQty = floor(
    (finalSystemKw × deeming_period × postcode_zone_factor) / 1.382
)
// 示例: floor((9.24 × 6 × 1.382) / 1.382) = 55

// 2. STC补贴金额
pvStcRebate = pvStcQty × pv_stc_price
// 示例: 55 × 39 = $2,145
```

#### 电池STC补贴

```javascript
// 1. 可用电池容量 (90% DoD)
usableBatteryCapacity = selectedBatteryKwh × 0.9
// 示例: 9.6 × 0.9 = 8.64 kWh

// 2. 电池STC数量
batteryStcQty = floor(usableBatteryCapacity × battery_stc_factor)
// 示例: floor(8.64 × 9.3) = 80

// 3. 电池STC补贴
batteryStcRebate = batteryStcQty × battery_stc_price
// 示例: 80 × 39 = $3,120
```

## 自检问题列表

### ⚠️ 发现的问题

#### 1. 容配比逻辑问题 ❌

**问题描述：**
```javascript
const dcAcRatio = batteryKwh < 7.0 ? smallRatio : largeRatio;
```

**问题：**
- 容配比应该基于**逆变器功率**而不是**电池容量**
- 当前逻辑：电池容量决定容配比
- 正确逻辑：应该根据系统规模（逆变器功率）决定

**建议修复：**
```javascript
// 方案1: 基于逆变器功率
const dcAcRatio = inverterKw < 6.0 ? smallRatio : largeRatio;

// 方案2: 基于系统类型
const dcAcRatio = strategyType === 'C' ? smallRatio : largeRatio;

// 方案3: 可配置
const dcAcRatio = config.strategies[strategyType].dc_ac_ratio || 1.5;
```

#### 2. 标准规格匹配的边界条件 ⚠️

**问题描述：**
```javascript
if (bat >= targetCapacity * 0.9) {
    selectedBatteryKwh = bat;
    break;
}
```

**问题：**
- 90%的阈值是否合理？
- 如果目标容量是5.5kWh，会选择5.0kWh（不足）还是9.6kWh（过大）？

**当前行为：**
- 5.5 × 0.9 = 4.95，会选择5.0kWh ✅
- 但5.0kWh实际小于5.5kWh，可能不够用

**建议：**
```javascript
// 更保守的策略：选择不小于目标容量的最小规格
for (let bat of standardBatteries) {
    if (bat >= targetCapacity) {  // 移除0.9系数
        selectedBatteryKwh = bat;
        break;
    }
}
```

#### 3. 峰值功率计算的安全系数 ⚠️

**问题描述：**
```javascript
peakPowerKw = dailyAvgKwh * maxHourlyRatio * 1.5;
```

**问题：**
- 1.5倍安全系数是否过大？
- 会导致逆变器选型偏大，增加成本

**影响分析：**
```
日均用电: 21.92 kWh
最大小时比例: 6.23%
理论峰值: 21.92 × 0.0623 = 1.37 kW
实际峰值: 1.37 × 1.5 = 2.05 kW
```

**建议：**
- 1.2-1.3倍可能更合理
- 或者作为可配置参数

#### 4. 逆变器选型的70%覆盖率 ⚠️

**问题描述：**
```javascript
const peakLoadCoverage = peakLoadKw * 0.7;
```

**问题：**
- 为什么只覆盖70%的峰值负载？
- 如果峰值功率已经乘以1.5安全系数，再乘0.7相当于1.05倍，意义不大

**计算链条：**
```
理论峰值: 1.37 kW
× 1.5 (安全系数) = 2.05 kW
× 0.7 (覆盖率) = 1.44 kW
最终只比理论峰值大5%
```

**建议：**
- 要么去掉1.5安全系数，保留0.7覆盖率
- 要么去掉0.7覆盖率，保留1.5安全系数
- 或者调整为1.0覆盖率

#### 5. 电池充放电倍率固定为0.5C ⚠️

**问题描述：**
```javascript
const minInverterKwByBattery = batteryKwh * 0.5;
```

**问题：**
- 0.5C倍率对所有电池都适用吗？
- 不同品牌/型号的电池可能有不同的C-Rate

**建议：**
- 从配置读取：`config.battery.c_rate`
- 已经有这个配置项，但没有使用

#### 6. 面板排布时的效率权重 ⚠️

**问题描述：**
```javascript
const sortedPlanes = [...roofPlanes].sort((a, b) => b.efficiency - a.efficiency);
```

**问题：**
- 只按效率排序，没有考虑坡面容量
- 可能导致高效率小坡面优先，浪费大坡面

**示例：**
```
坡面A: 效率1.0, 最大5块
坡面B: 效率0.95, 最大50块
目标: 40块

当前逻辑: A装5块, B装35块
更优逻辑: 可能应该考虑容量利用率
```

**建议：**
- 考虑效率和容量的综合评分
- 或者提供多种排布策略

#### 7. 不含电池的kW单价计算 ⚠️

**问题描述：**
```javascript
pricePerKwWithoutBattery = (panelCost + inverterCost) / pvKw
```

**问题：**
- 这个指标的实际意义是什么？
- 逆变器成本应该算在内吗？

**分析：**
- 如果是评估光伏系统性价比，应该只算面板成本
- 如果是评估整体系统（不含电池），当前公式正确

**建议：**
- 明确指标定义
- 或者提供两个指标：
  - 纯光伏kW单价 = panelCost / pvKw
  - 光伏+逆变器kW单价 = (panelCost + inverterCost) / pvKw

#### 8. STC计算中的zone_factor缺失 ❌

**问题描述：**
```javascript
pvStcQty = floor((finalSystemKw × deeming_period × 1.382) / 1.382)
```

**问题：**
- 1.382是zone 3的系数，硬编码了
- 不同postcode应该有不同的zone系数

**正确逻辑：**
```javascript
const zoneFactor = getZoneFactorByPostcode(postcode);
pvStcQty = floor((finalSystemKw × deeming_period × zoneFactor) / 1.382)
```

**Zone系数表：**
| Zone | 系数 | 地区 |
|------|------|------|
| 1 | 1.622 | 北部（达尔文等）|
| 2 | 1.536 | 中部 |
| 3 | 1.382 | 南部（悉尼、墨尔本等）|
| 4 | 1.185 | 塔斯马尼亚 |

#### 9. 最小串联数检查的时机 ⚠️

**问题描述：**
```javascript
if (maxPanels < minPanelsPerString) {
    // 移除坡面
}
```

**问题：**
- 在分配前检查最大容量
- 在分配后又检查实际分配数量
- 逻辑重复

**建议：**
- 统一在分配前过滤不合格坡面
- 或者只在分配后检查

#### 10. 配置参数的默认值处理 ⚠️

**问题描述：**
```javascript
const smallRatio = parseFloat(document.getElementById('config_battery_small_ratio').value) || 1.5;
```

**问题：**
- 如果元素不存在，会返回null
- `parseFloat(null)` = NaN
- `NaN || 1.5` = 1.5 ✅ (这个是对的)

**但是：**
```javascript
const matchStandard = document.getElementById('config_battery_match_standard').checked;
```

**问题：**
- 如果元素不存在，会抛出异常
- 应该添加null检查

**建议：**
```javascript
const matchStandard = document.getElementById('config_battery_match_standard')?.checked || false;
```

## 总结

### ✅ 做得好的地方

1. **清晰的五步流程** - 逻辑分层合理
2. **策略化设计** - 三种方案满足不同需求
3. **配置化参数** - 灵活可调整
4. **标准规格匹配** - 符合实际产品规格
5. **物理约束验证** - 考虑了电压和空间限制

### ⚠️ 需要改进的地方

1. **容配比逻辑** - 应基于系统规模而非电池容量
2. **安全系数调整** - 1.5倍可能过大
3. **覆盖率逻辑** - 与安全系数重复
4. **Zone系数** - 需要根据postcode动态获取
5. **边界条件处理** - 90%阈值需要重新评估
6. **null检查** - 需要更完善的错误处理

### 🎯 优先级建议

**高优先级（影响计算准确性）：**
1. 修复Zone系数硬编码问题
2. 重新评估容配比逻辑
3. 调整安全系数和覆盖率

**中优先级（影响用户体验）：**
4. 完善null检查和错误处理
5. 优化标准规格匹配阈值
6. 改进面板排布策略

**低优先级（优化建议）：**
7. 明确kW单价指标定义
8. 使用配置的C-Rate参数
9. 清理重复的检查逻辑

```javascript
]

```

### 计算过程

```
第1步：负载分析
  日均用电: 8000 / 365 = 21.92 kWh
  夜间比例: 45.23%
  夜间用电: 21.92 × 0.4523 = 9.91 kWh
  峰值功率: 21.92 × 0.0623 × 1.5 = 2.05 kW

第2步：电池定容
  目标容量: 9.91 × 1.0 = 9.91 kWh
  标准匹配: 9.6 kWh (最接近的标准规格)

第3步：逆变器选型
  充放电需求: 9.6 × 0.5 = 4.80 kW
  峰值覆盖: 2.05 × 0.7 = 1.44 kW
  目标功率: max(4.80, 1.44) = 4.80 kW
  标准匹配: 5.0 kW

第4步：光伏反推
  容配比: 1.8 (电池≥7kWh)
  目标功率: 5.0 × 1.8 = 9.0 kW
  目标面板数: ceil(9000 / 440) = 21 块

第5步：物理排布
  最小串联数: ceil(100 / 32) = 4 块
  坡面A: 安装10块 ✅
  坡面B: 安装8块 ✅
  剩余: 3块 (无法安装)
  最终: 18块, 7.92 kW

成本计算:
  面板: 7.92 × 1200 = $9,504
  逆变器: 5.0 × 280 = $1,400
  电池: 9.6 × 865 = $8,304
  税前: $19,208
  GST: $1,921
  含税: $21,129
  
补贴:
  STC PV: 47 × 39 = $1,833
  STC Battery: 80 × 39 = $3,120
  总补贴: $4,953
  
最终报价: $21,129 - $4,953 = $16,176
```
